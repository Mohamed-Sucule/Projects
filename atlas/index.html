Case study

Tally: an AI analyst that checks every supplier invoice

Python · FastAPI · Claude · SQLite

The problem

“We pay hundreds of supplier invoices a month and nobody has time to check them against the contracts.”

What it does

Tally reads the supplier contracts and the accounts export. It answers questions with cited sources, audits every invoice against the terms in force on its date, and drafts the dispute emails, which a person approves before anything goes out.

Architecture

ReadContracts: PDF, Word, HTML, Markdown→checked by content, parsed with limits, chunked by heading→full-text index, injection flags·Accounts CSV→validated into a separate database
AnswerQuestion→Claude⇄search · read · read-only SQL · calculator→every quote checked word for word→answer streamed to the page
ActClaude extracts contract terms, with quotes→plain code audits every invoice line→Claude drafts dispute emails→guardrails: every invoice, every £→a person approves→outbox

Claude   a person   everything else is ordinary, tested code.

Where the AI is, and where it isn’t

  • Claude reads. It answers questions using tools, and turns each contract into typed terms, each with a quote that must be found in the source.
  • Code decides. Whether money is owed is worked out by plain Python, tested to the penny, so no note on an invoice can talk it out of a finding.
  • People approve. No email leaves until someone has read it, edited it or rejected it.

Decisions and trade-offs

  • Keyword search before embeddings. Contract language is exact, and the retrieval eval found the right document for every test question. Embeddings wait until an eval shows a miss.
  • Structured output plus a quote check. The schema guarantees the shape; the quote check catches a term the model invented.
  • One process and SQLite. Right for one business. Several would need Postgres and a shared rate limiter.
  • Built to be run. Refusal fallbacks, a daily spending cap, every call’s cost logged, an admin token, rate limits and a strict content policy.
