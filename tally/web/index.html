Ask about suppliers, contracts and invoices

Tally searches the contracts, queries the accounts with read-only SQL and does the arithmetic with a calculator tool. Every quote it cites is checked against the source before you see it.

Invoice audit

Deterministic checks of every invoice line against the contract terms: prices in force on the date, discounts, delivery charges, allowances, fees, duplicates and arithmetic. Claude drafts the dispute emails; a person approves each one.

Documents and accounts

PDF, Word, HTML and Markdown documents are parsed, split by heading and indexed for search. Text that tries to instruct an AI is flagged at ingestion.

Evals

Answers are graded against facts computed from the data, not by another model: the right number within a tolerance, the right status, a citation to the right document, no instruction followed from a document.

How Tally works

  1. Ingest. Contracts arrive as PDF, DOCX, HTML or Markdown. Each is sniffed by content (not extension), parsed with size, page and zip-bomb limits, chunked by heading and indexed with SQLite FTS5. The accounts export (CSV) loads into a separate database.
  2. Ask. Claude answers with five tools: document search, document reading, a SQL tool that can only read six named tables (enforced by a SQLite authorizer, a read-only connection and a step budget), a list of documents and an exact calculator. The answer comes back as structured JSON.
  3. Verify. Each citation must quote, word for word, a passage the model was actually shown; anything else is removed and the reader is told. Text from documents and the database is wrapped as untrusted data, and money decisions are never made by the model.
  4. Extract. Claude turns each supplier's contract and amendments into typed terms (prices with effective dates, fees, discounts, allowances), each with a quote that must appear in the source.
  5. Audit. Plain code checks every invoice line against those terms and produces findings with amounts. It is tested against 23 errors planted in the demo books.
  6. Act. Claude drafts one dispute email per supplier. Guardrails check that every invoice is mentioned and every £ figure is one the audit produced. A person edits, approves or rejects; approved emails go to an outbox.

Production details

  • Refusal fallbacks enabled server-side; typed handling of rate limits, overload, timeouts and auth errors.
  • Prompt caching on system prompts; per-call token and cost accounting with a daily budget cap.
  • Per-client rate limits, request size limits, admin token for uploads, strict CSP and security headers.
  • Offline test suite with a scripted model; CI runs it on every push, and the model evals run when an API key is available.
